# SpecForge システム設計仕様書 (System Architecture & Design Specification)

**システム名称**: SpecForge（プラント配管・機械設備 仕様書作成＆機器データベース管理システム）  
**バージョン**: Ver 2.0.0  
**作成日**: 2026年11月10日  
**対象環境**: Webブラウザ（Chrome, Edge, Safari） / デスクトップPWA（Windows, macOS）

---

## 1. システム概要と開発目的

### 1.1 開発背景と目的
プラント配管・産業機械調達における機器仕様書の作成業務では、以下のような課題が存在していました。
- 案件共通情報（案件名、案件コード、発注元、オーダーNo.）の複数機器仕様書への手動転記ミス
- 会社指定のExcel原本テンプレートの書式崩れ・結合セルの破損・フォント崩れ
- 機器仕様（口径、耐圧、流量、材質等）の設計変更履歴の散逸
- 複数機器を1枚の仕様書にまとめて調達する際のセル位置調整の手間

本システム（SpecForge）は、**「機器データベースの一元管理」** と **「Excel原本レイアウトの完全保持（Zero Layout Break）」** を両立し、Webブラウザおよびデスクトップ上でリアルタイムに仕様書の編集・プレビュー（PDF/Excel）・一括出力を行えるように開発された専用エンジニアリングシステムです。

### 1.2 コアバリュー
1. **Excel原本の完全保持**: アップロードした原本.xlsxのバイナリをBase64で保持し、ExcelJSによりセル番地へ直接値を注入。フォント、罫線、行高、列幅、会社ロゴ、結合セルを1ピクセルも崩さず出力。
2. **直感的な2モードプレビュー**: 
   - **PDF (仕様書帳票)**: A4印刷帳票をキャンバス上に実寸比率で直接描画。
   - **EXCEL (原本直接描画)**: ExcelJSのインメモリ解析によるスプレッドシート表示（数式バー・セル連動）。
3. **機器種別コード連動と新採番ルール**: 機器種別（アルファベット2文字）と案件コードから、`${案件コード}${機器種別}G-${機器番号}` を自動生成。
4. **最大4機器並列セルマッピング**: 1つの仕様書内に最大4種類（1種類目〜4種類目）の機器パラメータを並列マッピング・流し込み可能。
5. **完全な監査証跡（Audit Trail）**: 機器情報編集モーダル内に変更メモ欄と過去の変更履歴（変更前/変更後/理由/更新者/日時）を直結表示。

## 4. 機能設計仕様

### 4.1 案件管理（プロジェクト・ワークスペース）機能
1. **2ペイン構成の案件一覧**:
   - 左ペイン: 現在選択されているアクティブ案件のコード、名称、客先名、機器点数、概要を表示。右下の「基本情報編集」ボタン押下時のみ編集モーダルを開く（カード本体クリックでの不要な画面遷移を抑止）。
   - 右ペイン: 登録済みの全案件リストを一覧表示。ワンクリックで作業対象案件を瞬時にスイッチ。
2. **案件コードの構造化**:
   - `codePart1`（年度・工事区分など）と `codePart2`（連番・枝番など）に分割入力対応。自動的に `${codePart1}-${codePart2}` として統合。
3. **客先番号の廃止**:
   - 要求仕様に基づき、新案件作成モーダルおよびサマリー表示部から客先番号入力欄を完全撤廃。
4. **JSON正本ファイル連動**:
   - 案件ごとにローカルJSONファイルを正本データベースとして紐づけ、バックアップ・復元が可能。
5. **案件登録の安全削除（2クッション確認＆JSON正本ファイル保持）**:
   - 案件サマリーの基本情報編集モーダル最下部に、控えめなサイズで「この案件登録を削除」ボタンを設置。
   - 誤操作・誤爆を防ぐため、**2段階（2クッション）の確認ステップ**（ステップ1: 画面削除確認とJSON保持の説明 → ステップ2: 最終実行確認）を要求。
   - **完全保全設計**: 削除処理はアプリ画面およびブラウザの登録リストからのみ登録を解除。**PCのディスク上にあるJSONファイル正本は絶対に消去・変更されずそのまま安全に保持**されるため、後からいつでもJSONファイルを開いて再読み込み可能。

### 4.2 機器データベース管理機能
1. **機器番号の区分別ナンバリング（03: 購入品 / 04: 製作品 / 08: 設計込）**:
   - 機器番号の頭部区分（プレフィックス）をプルダウン選択式に標準化:
     - `03`: **購入品**（バルブ、汎用計器、標準調達品など）
     - `04`: **製作品**（製作品、加工配管、特注ポンプユニット、オーダータンクなど）
     - `08`: **設計込**（詳細設計、強度計算、特注設計製作一括品など）
   - 後半のナンバリングは、区分ごとに記載順で 1 から順に3桁連番（`03-001`〜、`04-001`〜、`08-001`〜）として自動付番。
2. **連番の自動繰り下がり＆空き詰め連動（Auto-Resequencing）**:
   - 重複や順序変更時の自動シフトアルゴリズム:
     - 例: `04-001` の区分を `03-001` に変更した場合、既存の `03-001` は自動的に `03-002` に繰り下がり、それに続く既存番号（`03-002`→`03-003`...）も1つずつ安全に繰り下がる。
     - 同時に、移動元の `04` グループは空いた番号が自動で詰められ、`04-002` が `04-001` に繰り上がって欠番・重複のない完全な連番を維持。
     - `08: 設計込` グループとの相互変更時も同様に自動シフトと空き詰めが安全に機能。
3. **区分絞り込みフィルター（サイドバー）**:
   - 左サイドバーに「機器区分（ナンバリング）」カードを配置し、「区分すべて」「03: 購入品」「04: 製作品」「08: 設計込」をワンクリックで瞬時に絞り込み可能。機器一覧上ではマーク等の装飾を省きプレーンな機器番号のみを表示。
4. **機器種別（英大文字2文字）のプレーン文字列表示**:
   - バルブ（`VA`）、ポンプ（`PU`）、タンク（`TK`）、熱交換器（`HE`）など、2文字の識別コードを機器ごとに定義。
   - 機器一覧テーブルにおいて、囲み枠を排したシンプルなプレーン文字列として「機器番号」列の左隣に常時表示。
5. **仕様書発行欄（未 / 済）の表示（表示専用・文字列のみ＆済行の約30%グレー表示）**:
   - 機器一覧データベーステーブルにおいて、**「納入時期」列の右側に「発行」列** を新設。
   - 誤操作（誤爆）を防止するため、一覧上でのクリック切り替えを抑止した**安全な表示専用設計**。
   - バッジや装飾枠を排した**シンプルな文字列のみ（「済」または「未」）**で表示。
   - 発行状態が「済」の機器行は、**背景色を約30%のグレー（`bg-slate-200/60`）**で表示し、発行済みの機器が一目で直感的に識別可能。
   - 編集は機器編集画面内のチェックボックスからのみ実行可能。
   - 検索バーで「未」「済」による機器の即時絞り込みに対応。
6. **一括編集（Batch Edit）機能**:
   - 複数機器をチェック選択後、一括操作バーから以下を実行可能:
     - **機器種別の一括変更**: 2文字のアルファベットを入力し、対象機器を一括更新。変更履歴に「機器種別の一括更新」として自動記録。
     - **納期の一括変更**: カレンダーまたは任意テキストを入力し、対象機器の納期を一括更新。
     - **カテゴリ一括移動 / 一括削除**。
7. **機器編集・登録画面のレイアウト最適化**:
   - 機器編集モーダル（`ItemEditModal`）および登録モーダル（`ItemCreateModal`）において、**数量・単位の右側に「仕様書発行」チェック欄** を配置。
   - 従来の横並び配置を見直し、**「特記事項・指示事項」入力欄を一段下に下げて幅いっぱいに拡張**。入力視認性と操作性を大幅に向上。
8. **変更メモ＆直結変更履歴ログ**:
   - 機器情報編集モーダルにおいて、フォーム下部に「変更理由・作業メモ」入力欄を配置。
   - その直下に、その機器固有の「変更履歴ログ一覧」をタイムライン形式で常時表示。変更前後の値（発行状態の未→済含む）、変更者、日時、メモを即座に確認可能。

### 4.3 テンプレート・マッピング設定機能
1. **仕様項目名の重複排除プルダウン**:
   - セル番地マッピングの項目名登録時、手入力を廃止し、現在機器データベースに登録されている全機器の仕様項目名（口径、耐圧、流量、材質等）から重複を除外してプルダウン候補を自動生成。
2. **4スロット並列マッピング**:
   - 1つの仕様項目に対して、以下の4つのセル番地を並列設定可能:
     - 1種類目（主仕様）セル番地（例: `C15`）
     - 2種類目 セル番地（例: `D15`）
     - 3種類目 セル番地（例: `E15`）
     - 4種類目 セル番地（例: `F15`）
3. **チェックボックス専用マッピング**:
   - チェックボックス値を出力するセル番地と、項目名を出力するラベルセル番地を個別に指定可能。
   - ON時の文字列（例: `☑ 要`、`要`、`○`）とOFF時の文字列（例: `☐ 不要`、`不要`、`-`）を自由に設定可能。
4. **基本情報マッピング**:
   - 案件名、仕様書番号、発行日、客先名、工事場所等の案件共通項目を個別のセル番地にバインド。

### 4.4 仕様書リアルタイム生成・プレビュー機能
1. **仕様書番号の自動生成ルール**:
   - 計算式: **`${案件コード}${機器種別}G-${機器番号}`**
   - 例: 案件コード `PRJ-2026-01`、機器種別 `VA`、機器番号 `03-001` の場合:
     $$\text{仕様書番号} = \text{PRJ-2026-01VAG-03-001}$$
   - 案件コードと機器種別の間にハイフンを入れず、種別末尾に「G」を付与。機器番号（`03-001` や `04-001`）とハイフン結合。
2. **対象機器の複数選択**:
   - 仕様書に含める機器を複数選択可能。
   - 選択された機器の中から「主仕様（1種類目）」をラジオボタンで選択。追加された機器は自動的に2種類目〜4種類目としてスロットに割り当て。
3. **タブ切り替え式プレビュー**:
   - **「📄 PDF (仕様書帳票)」タブ**:
     - 読み込まれたExcel原本テンプレート（登録テンプレートまたは独自アップロード原本）をExcelJSでインメモリ解析し、各セル番地にデータを流し込んだ状態で、実寸A4比率のPDF帳票として直接描画。
     - テンプレート原本のタイトル、罫線、行高、列幅、結合セル、背景色、フォントスタイルがそのまま反映された真の「原本準拠PDFプレビュー」として表示。
     - 「🔄 再読み込み」ボタン押下により、入力データやマッピングの変更を瞬時に画面反映。
   - **「📊 EXCEL (原本直接描画)」タブ**:
     - ExcelJSがメモリ内に展開したスプレッドシートを行番号・列文字（A, B, C...）付きで完全再現描画。
     - 読み込み元Excelテンプレートの各列文字幅（MDW基準）・行高さ（pt基準）をピクセル換算し、`table-layout: fixed` と `<colgroup>` によりセルサイズを完全一致再現。
     - セル罫線（細線、中線、二重線等）および背景色、フォント、文字配置（横・縦）もテンプレート原本通り忠実に描画。
     - **枠内拡大縮小（Zoom）機能**: ExcelJSプレビュー枠内のツールバーから `[-]`、`[+]` ボタン、クイック倍率プリセット（`75%`、`100%`、`125%`）、および `Ctrl + マウスホイール` による直感的なズーム操作に対応。
     - 数式バー（`fx`）と連動し、セルをクリックすると番地・値・バインド項目が表示され、直接編集可能。
4. **統合出力ボタン (`[ ⬇️ 出力 ▼ ]`)**:
   - 出力アクションを1つのドロップダウンボタンに集約。
     - **📄 PDF出力 (.pdf)**: 画面上に描画されているA4帳票を直接キャプチャし、jsPDFでベクターPDFファイルとしてダウンロード。
     - **📊 Excel出力 (.xlsx)**: ExcelJSにより原本テンプレートバイナリに各セル値・明細行を注入し、原本と全く同じフォーマットのExcelファイルをダウンロード。

## 5. セキュリティ・信頼性設計
1. **クライアント完結型アーキテクチャ**:
   - すべてのExcelJS処理、DOMキャプチャ、PDF生成はブラウザのインメモリ上で高速実行。機密性の高いプラント機器仕様情報や図面番号が外部サーバへ送信されるリスクをゼロ化。

3. **完全な履歴保持**:
   - 変更履歴ログはタイムスタンプとともに不変配列として保管され、不正な改ざんを防止。
